INTERPRETATION AND NEXT TESTS
1. Keep phase-timing interventions distinct from component isolation. Delaying SD until after STOP lowers the capture-period load, but includes CPU work, SD bus activity and card demand together.
2. Hold versus sensor-reset middle windows isolate an incremental post-STOP reset benefit with a matched busy loop. Do not subtract the 79 mA awake floor from the separate 8.7 mA cold Standby plateau as if they were the same state.
3. Prioritize independent Ethernet PHY power-down versus its matched control, then relevant MCU clock/peripheral gating. U24 remains a real candidate for overhead, but these traces alone do not quantify it.
4. Reduce scan cost or add a validated allocation hint: the current scan reads one header per previously used slot. More occupied slots confound whole-cycle comparisons, so retain scan count and phase energy for every trial.
5. Characterize the SD write loop separately: current plots do not distinguish each data transfer from each card-busy interval. Match bytes, card state and fixed SD kernel clock when evaluating CPU sleep/frequency changes.
6. Qualify the excluded first 5 ms independently before claiming real inrush peak or complete-cycle energy. Source-side JS voltage does not establish target-side rail droop.

LIMITS
All scoped analysis windows have finite, contiguous analog samples and matching raw hashes. Original whole-session initial NaNs remain; final packed GPIO chunk is excluded.
Phase7 retains the legacy name padded_payload_ready but in the installed magic-slot path it occurs after successful transport return.
Warm DWT time is mapped to JS samples using piecewise GPIO/counter anchors; global-fit drift residuals are saved; do not interpret inferred counter boundaries as sub-microsecond truth.
Firmware completion and downloaded original frame are not, by themselves, independent SD readback. Any later root-run SD equality checks belong to their own records.
