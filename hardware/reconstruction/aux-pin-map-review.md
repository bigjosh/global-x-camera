# Auxiliary pin-map review

Reviewed 2026-09-05 for schematic reconstruction. Scope: power ICs, discretes, RTC, accelerometer, and connector/polarity conventions. This is a pin-map and electrical-type audit, not a complete circuit, footprint, power-budget, or manufacturing review. Source connectivity and physical pin numbers have not been changed.

Source: [native Flux export](../../imports/flux/2026-09-05/bigjosh-global-x-camera.flx), SHA-256 `6da7be0451f25cee64d67e8072e4fb0b201687bf9c56cfb6292dd439a3d16aac`, [native inventory](../../imports/flux/2026-09-05/native-inventory.json), and [reconciled physical connectivity](connectivity.json). Manufacturer pin tables were read from the archived PDFs; rendered polarity/package diagrams were inspected where extraction alone was insufficient.

[aux-pin-map-review.json](aux-pin-map-review.json) provides `pin_types[reference][physical_pin]` using KiCad tokens for 22 references and 147 pins. Every physical-pin key was checked against the recovered native terminal set. These recommendations override incorrect or missing native electrical-type metadata without changing the circuit. MCU, NOR, NAND, and camera module pin audits are outside this report.

## Findings to preserve in the reconstruction

1. **Confirmed metadata error: U7 pin 5 SW is typed `powerIn` in Flux.** It is the switch-node power output, and the KiCad recommendation is `power_out`. Pin 2 PG is open-drain (`open_collector` in KiCad). U2's three SW pins are physically terminals of the switch-node output; the ERC model retains one `power_out` and models its duplicate terminals as passive, as recorded below. An output type does not imply that these switch nodes are regulated DC rails.
2. **LED1 polarity is consistent after physical-net reconciliation; EDIF aliases must not be treated as pin numbers.** Native LED1 pins are both named `~`. An initial audit incorrectly assigned physical numbers by the EDIF duplicate-name ordering and raised a probable polarity mismatch. The native UUID-specific canonical anchor proves **physical pad 1 = STATUS_LED_K**; the remaining group member is **physical pad 2 = STATUS_LED_A**. This agrees with pad 1 on the footprint's cathode-marked side. The earlier probable-defect finding is withdrawn. ROHM's Figure 1 supplies cathode geometry rather than numeric pin labels. Preserve the reconciled numbers and nets; aliases such as `&__2` identify logical terminals and do not establish physical pad 2. [Connectivity evidence](connectivity-evidence.md), [ROHM SML-P11MTT86(R), p. 4, Figure 1](../../datasheets/controls/SML-P11MTT86R_datasheet.pdf).
3. **U10 pad 5 is an exposed-ground-pad library convention.** The manufacturer numbers the four perimeter terminals and lists EPAD separately without a numerical pin. Native pad 5 represents that EPAD. Retain 5 and its GND connection; do not drop it when selecting the XDFN4 package.
4. **U7/U10 footprints require the effective Flux corrections.** Their numeric pin maps match the manufacturer, but that does not validate the cached land patterns. U7 has nine mask/paste auxiliary shapes plus six electrical terminals; the board contains a correction removing defective imported copper. U10 has two board rules correcting custom corner lands. Preserve/apply those rules or independently rebuild the footprints against the manufacturer land drawings before PCB use. [Native recovery assessment](../../imports/flux/2026-09-05/native-inventory.md).

Important type choices:

- U2/U7 PG and U8 INT are `open_collector`, the KiCad token also used for open-drain outputs. RTC SDA is bidirectional; SCL and EVI are inputs; CLKOUT is an output.
- U12 CT is an output per the manufacturer table. QOD is physically an internally resistive switched discharge path, modeled as `passive` for ERC; it must not be modeled as a power source. The source ties QOD to VOUT, an explicitly supported connection. The first `open_collector` model caused an inappropriate generic driver-conflict finding on this supported analog connection; see the specific modeling correction below.
- U11 SDO/SA0 is bidirectional to represent its data-output/address-input functions. INT2 is bidirectional because it can serve as an external clock input in the documented conversion mode. INT1 is an output; SCL and CS are inputs; SDA is bidirectional.
- U4/U9 pin 4 and U11 pin 5 are passive in the JSON because the manufacturer permits these NC terminals to be tied to stated rails/ground. A KiCad `no_connect` electrical type would forbid a permitted connection. Explicit schematic no-connect marks may still express the current unused intent.
- Supply inputs, ground terminals, and required-ground EP/RES connections use `power_in`. These types identify needed power connectivity; any required power-source flags belong in the schematic and must represent the actual supply path.

## Review of the first generated ERC report

The first `erc.json` export reported 15 errors: seven undriven-power reports, seven duplicate switch-output reports, and one QOD/VOUT type conflict. These specific findings call for accurate source and symbol modeling, not disabling classes of electrical checks. The recommendations below leave signal connectivity unchanged.

| Reported issue | Specific justified model or annotation |
| --- | --- |
| U2 SW_1/SW_2/SW_3 output conflicts (2 reports) | Keep pin 1 `power_out`; set pins 2 and 3 `passive` as duplicate terminals of the same switch node. Reconciled connectivity confirms all three are on `BUCK3V3_SW`. All physical pins remain visible and connected. The JSON now implements this duplicate-terminal convention. |
| U1 VLXSMPS_1 through VLXSMPS_6 output conflicts (5 reports) | Keep J1 `power_out`; model J2-J6 as passive duplicate switch-node terminals. Reconciled connectivity confirms all six are on `MCU_SMPS_SW`. This recommendation is for the generator's separately maintained MCU model; the auxiliary JSON does not overwrite U1's complete pin-type map. |
| U12 QOD connected to its VOUT (1 report) | Set pin 5 QOD `passive` as the analog discharge terminal; retain pin 6 VOUT `power_out`. Both are on `ACCEL_1V8_SW`. [TPS22918 p. 13, section 8.3.2](../../datasheets/power/TI_TPS22918_datasheet.pdf) explicitly supports this connection and describes the internal pulldown resistance. This narrowly corrects the model; it does not change the net or disable general open-drain/output conflict checking. |
| `SYS_IN` undriven | Add a PWR_FLAG at the supply input downstream of the passive battery MOSFET path and USB diode. A passive switch/diode does not propagate KiCad's power-output classification. |
| `3V3`, `1V8`, `VCORE_0V81` undriven | Add a PWR_FLAG on each regulated output side of L1, L2, and L3 respectively. The existing power-output terminals are on the switching side; a passive inductor separates each from the regulated rail for ERC. |
| `USB_VBUS`, `BAT_CELL1_TAP`, `GND` undriven | Add PWR_FLAG annotations identifying the external USB source, RTC battery tap, and common supply return. These are existing external supplies, not additional hardware components. |
| External `BAT_PLUS` source | A PWR_FLAG is also appropriate to document the external battery source even though its present passive MOSFET endpoint did not produce an undriven-power report. |

Do not add redundant PWR_FLAG symbols to the camera LDO outputs, USB LDO output, or accelerometer switched output; those already have real `power_out` symbol drivers. Keep pin-conflict and undriven-power checks enabled. After the generator applies these specific changes, rerun ERC and compare connectivity to the reconciled source; a clean ERC report alone will not certify the circuit or footprints.
